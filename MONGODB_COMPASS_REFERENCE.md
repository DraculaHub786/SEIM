## 🗄️ Database Collections

### 1. **logs** Collection
**Purpose:** Stores all security event logs

**Sample Document:**
```json
{
  "_id": ObjectId("..."),
  "timestamp": ISODate("2026-04-01T15:30:00Z"),
  "source": "windows-server-01",
  "event_type": "failed_login",
  "ip_address": "192.168.1.100",
  "username": "admin",
  "severity": "medium",
  "details": {
    "event_id": 4625,
    "logon_type": 3
  }
}
```

**Indexes:**
- `timestamp_-1_event_type_1` (Compound)
- `ip_address_1`
- `source_1`
- `event_type_1`
- `timestamp_1` (TTL: 90 days - auto-deletes old logs)

**Common Queries:**
```javascript
// Find failed logins
{ "event_type": "failed_login" }

// Find logs from specific IP
{ "ip_address": "192.168.1.100" }

// Find logs from last hour
{ "timestamp": { "$gte": new Date(Date.now() - 3600000) } }

// High severity events
{ "severity": "high" }

// Logs from specific source
{ "source": "windows-server-01" }
```

### 2. **alerts** Collection
**Purpose:** Stores security alerts generated by detection engine

**Sample Document:**
```json
{
  "_id": ObjectId("..."),
  "timestamp": ISODate("2026-04-01T15:35:00Z"),
  "alert_type": "brute_force_attack",
  "severity": "high",
  "ip_address": "192.168.1.100",
  "username": "admin",
  "status": "open",
  "description": "Brute force attack detected: 12 failed login attempts",
  "failed_login_count": 12,
  "first_attempt": ISODate("2026-04-01T15:30:00Z"),
  "last_attempt": ISODate("2026-04-01T15:35:00Z")
}
```

**Indexes:**
- `timestamp_-1`
- `ip_address_1`
- `status_1`
- `severity_1`
- `status_1_severity_1_timestamp_-1` (Compound)

**Common Queries:**
```javascript
// Open alerts
{ "status": "open" }

// High severity alerts
{ "severity": "high" }

// Alerts from specific IP
{ "ip_address": "192.168.1.100" }

// Recent brute force alerts
{ "alert_type": "brute_force_attack", "status": "open" }

// Resolved alerts
{ "status": "resolved" }
```

---

### 3. **users** Collection
**Purpose:** Stores user accounts for the platform

**Sample Document:**
```json
{
  "_id": ObjectId("..."),
  "username": "admin",
  "email": "admin@siem.local",
  "password_hash": "$2b$12$...",
  "role": "admin",
  "permissions": ["view_logs", "view_alerts", "export_data", "manage_users"],
  "created_at": ISODate("2026-04-01T10:00:00Z"),
  "last_login": ISODate("2026-04-01T15:00:00Z"),
  "is_active": true
}
```

**Indexes:**
- `username_1` (Unique)
- `email_1` (Unique)
- `role_1`

**Common Queries:**
```javascript
// Find admin user
{ "username": "admin" }

// Active users
{ "is_active": true }

// Users by role
{ "role": "admin" }
```

## 🔍 Useful Aggregations in Compass

### 1. Top 10 IPs by Log Count
```javascript
[
  { $group: { _id: "$ip_address", count: { $sum: 1 } } },
  { $sort: { count: -1 } },
  { $limit: 10 }
]
```

### 2. Event Type Distribution
```javascript
[
  { $group: { _id: "$event_type", count: { $sum: 1 } } },
  { $sort: { count: -1 } }
]
```

### 3. Logs per Hour (Last 24 Hours)
```javascript
[
  { 
    $match: { 
      timestamp: { $gte: new Date(Date.now() - 86400000) } 
    } 
  },
  {
    $group: {
      _id: { 
        $dateToString: { format: "%Y-%m-%d %H:00", date: "$timestamp" }
      },
      count: { $sum: 1 }
    }
  },
  { $sort: { _id: 1 } }
]
```

### 4. Failed Login Attempts by IP
```javascript
[
  { $match: { event_type: "failed_login" } },
  { $group: { _id: "$ip_address", count: { $sum: 1 } } },
  { $sort: { count: -1 } },
  { $limit: 20 }
]
```

### 5. Severity Distribution
```javascript
[
  { $group: { _id: "$severity", count: { $sum: 1 } } },
  { $sort: { count: -1 } }
]
```

## 🛠️ MongoDB Compass Tips

### Navigating Collections
1. Click on **siem_db** in left sidebar
2. Click on collection name to view documents
3. Use **Filter** bar at top for queries
4. Click **Schema** tab to analyze data structure
5. Click **Indexes** tab to view performance indexes

### Export Data
1. Click **Export Collection** button
2. Choose JSON or CSV format
3. Select export location
4. Optionally filter before export

### Import Data
1. Click **Add Data** → **Import File**
2. Choose JSON or CSV file
3. Map fields if needed
4. Click **Import**

### View Explain Plan
1. Enter query in Filter bar
2. Click **Explain Plan** button
3. View execution stats and index usage

### Create Index (if needed)
1. Go to **Indexes** tab
2. Click **Create Index**
3. Specify field(s) and direction
4. Add options (unique, TTL, sparse)

## 📊 Schema Validation (Already Configured)

The `logs` collection has automatic validation:
```javascript
{
  $jsonSchema: {
    bsonType: "object",
    required: ["timestamp", "source", "event_type", "ip_address"],
    properties: {
      timestamp: { bsonType: "date" },
      source: { bsonType: "string" },
      event_type: { bsonType: "string" },
      ip_address: { bsonType: "string" }
    }
  }
}
```

## 🎯 Quick Actions in Compass

### View Real-Time Logs
1. Connect to `siem_db`
2. Open `logs` collection
3. Click refresh button to see new logs
4. Sort by `timestamp` descending

### Monitor Active Alerts
1. Open `alerts` collection
2. Filter: `{ "status": "open" }`
3. Sort by `severity` and `timestamp`

### Check User Accounts
1. Open `users` collection
2. View all user accounts
3. Check `last_login` timestamps

## 🆘 Troubleshooting

**Cannot see database:**
- Run the SIEM application first (`python app.py`)
- Database is created on first run
- Refresh Compass connection

**Connection timeout:**
- Check MongoDB service status
- Verify port 27017 is listening
- Check firewall settings

**Collections are empty:**
- Send test logs via API
- Use sample data generator
- Check application logs for errors
